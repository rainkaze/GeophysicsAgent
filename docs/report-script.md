# 结课汇报讲稿：工程物探勘察方案推荐 Agent

面向《工程地球物理导论》，题目「面向工程物探勘察方案推荐的 LLM Agent 设计与实现」。
全文可按 10–13 分钟讲完，加粗处是必须说出口的关键句。

## 一句话开场

> 我实现了一个**能出勘察方案、且数值不被模型改**的 Agent：
> 输入一段场地描述，输出八种方法的比选、反算的采集参数、外业工作量，以及可回放的全过程轨迹。

## 第一部分：知识库怎么建（约 3 分钟）

- 语料：教材《An Introduction to Geophysical Exploration》(3rd ed.) 与课程课件、外部权威来源；
- 教材先预处理成 **12 章 Markdown**（修连字、合断词、去页眉页脚、每页标 `[p.N]`），
  章节边界已用 PDF 书签逐章核对（印刷页码 = PDF 页码 − 13）；
- 课件与外部来源整理成 **17 条中文条目**，中文条目负责中文提问的召回，英文原文负责回引页码；
- 知识库是**文件即知识**：加一个 `.md` 文件，下一次请求即被索引，不用改代码；
- 检索是混合检索（BM25 词法 + text-embedding-v4 向量 + qwen3-rerank 重排，对齐 Dify）。

## 第二部分：架构——七层，只有一层用模型

```
intake 规则抽取 → retrieve 混合检索 → assess 八方法评估 → plan 模型写理由
      → verify 14 条规则校验（error 回灌修复）→ design 参数与工作量 → render 正文
```

**关键句：模型只在 plan 这一层出现，它不抽条件、不算数、不设计外业、不自检。**

## 第三部分：功能

八方法（GPR/直流电阻率/面波/地震折射/磁法/FDEM/TEM/DAS）逐项比选；按物理关系反算采集参数
（GPR 用 `λ=v/f`、分辨率 `λ/4`；电阻率深度约排列长度 0.25 倍；面波排列约 2.5 倍深度）；
外业布置与工作量；14 条规则校验与自动修复；模型不可用时降级为规则方案；多轮追问合并条件。

## 第四部分：能做到什么（现场例子）

输入：`灰岩场地，目标埋深 20~30 m，找溶洞，有钢筋和高压线干扰`

- 面波为主；直流电阻率、地震折射（均判"受限"，因钢筋/高压线）、FDEM、TEM 可作交叉验证；
- GPR 判"深度不可行（16 m < 30 m）"，磁法"3 m 不可行"，DAS"物性不匹配"；
- 外业：3 条主测线 + 7 条横测线，点距 3.5 m，约 291 点，成本指数 20.4（中档）；
- 全流程不调模型也能出方案（`mode=degraded`），这是"数字不靠模型"的直接证据。

内置场景 4（山区路基探测灰岩溶洞，15 m）的具体数字：

| 方法 | 结论 | 可念的依据 |
|---|---|---|
| 磁法 | 不适用 | 最大深度 3 m < 15 m |
| GPR | 受限 | 深度余量仅 1.07×，理论上限、实际打折 |
| DC/ERT | 主方法 | 余量 2.67× |
| 面波 / FDEM | 辅助 | 交叉验证 |

电极距 1.5 m、排列长度 70.5 m 是反算的：有效深度 ≈ 0.25 × 排列长度，15 m 目标需约 60 m 排列。
外业 3 条主测线 + 7 条横测线，总长 1.02 km，约 680 个测点，成本档"中"。

追问"埋深改成 60 m 呢？"→ 条件沿用、评估整体重算，多数方法转为深度不足；
点"新对话"再问同样的话 → 系统重新追问目标/介质/埋深。

## 第五部分：两种呈现（约 3 分钟）

> 同一套判据，本地跑一遍，Dify 上再跑一遍，逐字段对得上。

- **本地**：`analysis/` 是唯一事实来源，`agent/` 负责编排，FastAPI + Vue 出结构化界面；
- **Dify**：工作室 → Chatflow，三个 Python 代码节点 + 一个 LLM 节点，
  `code_node_assess.py` 是 `tables.py`/`calculator.py`/`physics.py` 的逐行移植；
- **一致性不是靠嘴说**：`dify/parity_test.py` 跑 7 目标 × 7 介质 × 6 埋深 × 3 干扰 = 882 组条件，
  每组比 8 个方法的 19 个字段，全部一致才输出 `PARITY OK`；
- **知识库同源**：`kb_export.py` 用同一个解析器切片段（1337 个），只把 `[p.N]` 与
  `<!-- meta -->` 改写成片段首行可见的"编号｜标题｜出处｜页码"，所以 Dify 侧也能回引页码。

**关键句：两种呈现，一套判据；数值不是"对齐"出来的，是同一段代码算出来的。**

顺带可以讲一个反面例子：第一版 Dify 代码节点只对齐了"推荐主方法"，
采集参数其实是另一套算法（DC 电极距 2.1 m vs 本地 1.5 m）——这就是为什么要写对拍脚本。

## 第六部分：结论

> 我把"勘察方案推荐"做成了**确定性物理计算 + 受约束的模型决策 + 规则校验**的可复现管线。
> 这说明：一是知识库是可核对的（每条都能翻到原书页码）；
> 二是"模型只写理由、数字由代码给"的方法可复现、可测试、失败可降级。

## 现场演示顺序（6 分钟）

1. 填一个场景 → 出方案 → 指出"GPR 被判深度不可行"的依据；
2. 点开"执行轨迹"，逐条讲 intake/assess/verify/design 各步在做什么；
3. 追问"埋深改成 60 m"，展示条件合并与整体重算；
4. 把模型 Key 关掉（`ENABLE_LLM=false`）再问，展示降级方案仍能出结果；
5. 切到 Dify，同一个场景再跑一遍 → 主方法、采集参数、外业工作量三项与本地并排对照；
6. 输入"我想做个物探"，展示两边都先追问、都不猜。

## 可能被问到的问题

| 问题 | 一句话答法 |
|---|---|
| 模型在哪一步？ | 只在写理由，数字全部来自代码 |
| 知识库为什么分中英两份？ | 教材是英文原文，中文条目负责中文提问召回，两者同源互补 |
| 数据真实吗？ | 教材全文带 `[p.N]` 页码标记可直接回引，数值表是教学区间且已声明 |
| 和直接问 ChatGPT 有什么区别？ | 数字不由模型决定，方案可复现、可测试、失败可降级 |
| 为什么还要在 Dify 上再做一遍？ | 证明这套判据不依赖某个框架：换平台、换运行时，数字不变 |
| 两个呈现怎么保证一致？ | 代码节点是逐行移植 + `parity_test.py` 882 组条件逐字段对拍 |
| 为什么 Dify 那边没有"修复"这一步？ | Chatflow 里带条件的回边循环不好讲，改成"不通过就直接换规则方案"，效果一样 |
| 局限性？ | 教材 2002 年版，GPR/面波/DAS 覆盖薄，页码引用可能差 1–2 页；分辨率尚未参与判据 |

## 最低限度要懂的五个概念

1. **Agent**：有目标、会调工具、能自检、失败可降级的系统；不是"会聊天的模型"。
2. **RAG**：先检索、再生成；本地用混合检索（BM25 词法 + 向量 + 重排）。
3. **工具调用**：确定性评估器（`analysis/`）就是一个"工具"，由运行时固定编排调用。
4. **校验/降级**：输出不合规就重写；写不出来就退回规则方案。
5. **可复现**：`temperature=0` + 同一份知识 + 同一套代码，同样输入同样输出。
